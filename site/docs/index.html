01 · Summary and objectiveResumen y objetivo

Replace the service without any client noticing

Reemplazar el servicio sin que ningún cliente lo note

What we build. An HTTP service that accepts exactly the same requests as the original and returns the same status and the same body, errors included. It also ships a specification that lets another engineer reimplement it without touching the original, and the experiment log that proves each claim.

Qué construimos. Un servicio HTTP que acepta exactamente los mismos requests que el original y devuelve el mismo status y el mismo cuerpo, errores incluidos. Además entrega una especificación que permite a otro ingeniero reimplementarlo sin tocar el original, y el log de experimentos que prueba cada afirmación.

For whom. The company that depends on the service (its clients must not notice the swap) and the engineers who will maintain it after the people who wrote it left.

Para quién. La empresa que depende del servicio (sus clientes no deben notar el cambio) y los ingenieros que lo mantendrán ahora que sus autores ya no están.

What it turned out to be. A small core-banking protocol over POST /msg: open accounts, check balances, deposit, transfer and reverse operations, with a mod-97 checksum per message, per-client state, a transfer limit and an account lock.

Qué resultó ser. Un pequeño protocolo de core bancario sobre POST /msg: abrir cuentas, consultar saldos, depositar, transferir y anular operaciones, con un checksum mod 97 por mensaje, estado por cliente, un límite de transferencia y un bloqueo de cuenta.

Expected result. ≥ 95 of the 100 hidden tests passing at 20:00, every documented behavior backed by a cited experiment, and zero false claims in the specification.

Resultado esperado. ≥ 95 de los 100 tests ocultos aprobados a las 20:00, cada comportamiento documentado respaldado por un experimento citado y cero afirmaciones falsas en la especificación.

Known facts vs assumptions

A hypothesis is never presented as a requirement. Confidence: confirmed = probed and repeated; probable = seen once or inferred; assumed = not probed, it is the replacement's default.

05 · Proposed architectureArquitectura propuesta

The experiment log drives both the replacement and its tests

El log de experimentos guía tanto el reemplazo como sus tests

Two halves with a hard boundary: exploration tooling that is the only thing allowed to reach the original, and the replacement, which never calls it.

Dos mitades con un límite estricto: las herramientas de exploración, que son lo único que puede tocar el original, y el reemplazo, que nunca lo llama.

Architectural style: a layered monolith with a validation pipeline

Estilo arquitectónico: monolito en capas con un pipeline de validación

One process, four layers. Dependencies point only downward, so the protocol can be tested without HTTP and the state knows nothing about the rules. Inside the application layer, validation is a pipes-and-filters chain where the first failing check answers.

Un proceso, cuatro capas. Las dependencias solo apuntan hacia abajo: el protocolo se prueba sin HTTP y el estado no conoce las reglas. Dentro de la capa de aplicación, la validación es una cadena tipo pipes-and-filters donde responde el primer chequeo que falla.

Domain model and invariants

Modelo de dominio e invariantes

Account AC-0001…: name, balance, consecutive rejected transfers, locked, intentos (v2).
Operation OP-0001…: deposit or transfer, amount, accounts, reversed.

Cuenta AC-0001…: nombre, saldo, transferencias rechazadas consecutivas, bloqueada, intentos (v2).

  • Ids are sequential per token and restart after a reset
  • An operation is reversed at most once
  • A locked account can still receive funds and deposits; a successful deposit lifts the lock
  • A transfer never moves more than the limit or the balance
  • Los ids son secuenciales por token y reinician tras un reset
  • Una operación se anula como máximo una vez
  • Una cuenta bloqueada aún puede recibir fondos y depósitos; un depósito exitoso levanta el bloqueo
  • Una transferencia nunca mueve más que el límite o el saldo

The checksum

El checksum

control = 98 − (N mod 97)

Found by noticing that changing one digit moved the control by −3 modulo 97, the signature of a mod-97 check like IBAN, then searching letter mappings until all valid examples matched. N = the message without its control, uppercased; A=1…Z=26, digits kept, other characters dropped, 00 appended. Compared as exact text.

Lo encontré al notar que cambiar un dígito movía el control en −3 módulo 97, la firma de un check mod 97 como el IBAN, y luego probando mapeos de letras hasta que todos los ejemplos válidos coincidieron. N = el mensaje sin su control, en mayúsculas; A=1…Z=26, dígitos igual, otros caracteres eliminados, 00 al final. Se compara como texto exacto.

Una línea de log estructurada por request: ruta, comando, status, código de error, latencia. Health check para liveness. El diff harness es el monitor de corrección.

Test strategy

Estrategia de pruebas

Unit

Unitarias

Checksum against every valid and invalid example; amount parser at 0, 1, 9,999,999,999 and 10,000,000,000; lock counter transitions (fail, fail, success, fail×3).

Checksum contra cada ejemplo válido e inválido; parser de montos en 0, 1, 9.999.999.999 y 10.000.000.000; transiciones del contador de bloqueo (falla, falla, éxito, falla×3).

Integration

Integración

Pipeline order: one test per adjacent pair of checks, each request carrying both faults (e.g. bad amount + same account → E303).

Orden del pipeline: un test por par vecino de chequeos, cada request con ambas fallas (ej. monto inválido + misma cuenta → E303).

End to end

Extremo a extremo

The diff harness replays the 20 public examples and every logged sequence against the local and the deployed replacement — the same shape as the hidden set.

El diff harness reproduce los 20 ejemplos públicos y cada secuencia del log contra el reemplazo local y el desplegado, con la misma forma que el set oculto.

Non-functional

No funcionales

Latency burst; restart then health check; requests without and with a wrong token on every route; a 1 MB body.

Ráfaga de latencia; reinicio y luego health check; requests sin token y con token inválido en cada ruta; un cuerpo de 1 MB.

Criterios de aceptación

  • Every spec row cites at least one log id, with its confidence
  • Los 20 ejemplos públicos pasan en orden tras un reset
  • Todas las secuencias de la versión vigente pasan, en local y desplegado
  • El reemplazo hace cero requests salientes (verificado en revisión de código y logs)
  • Health en verde en la URL pública desde las 20:00
  • Cada fila de la spec cita al menos un id del log, con su confianza

Inherited risks a new client should not copy

Riesgos heredados que un cliente nuevo no debería copiar

Reversals ignore balances and can leave an account negative. Fix: reject a reversal that would overdraw, or record a debt.

Las anulaciones ignoran el saldo y pueden dejar una cuenta en negativo. Solución: rechazar la anulación que sobregire o registrar una deuda.

No idempotency key: a retried DEPOSITO or TRANSFER applies twice. Fix: a client-supplied request id.

Sin clave de idempotencia: un DEPOSITO o TRANSFER reintentado se aplica dos veces. Solución: un id de request enviado por el cliente.

The mod-97 checksum detects typos, not tampering: anyone can compute it. Fix: an HMAC with a shared secret.

El checksum mod 97 detecta errores de digitación, no manipulación: cualquiera lo calcula. Solución: un HMAC con secreto compartido.

PING skips integrity; inconsistent field names (cuentaId / cuenta_id) and a typo (recieved) are part of the contract. Fix: a versioned v2 API.

PING se salta la integridad; nombres inconsistentes (cuentaId / cuenta_id) y un error de tipeo (recieved) son parte del contrato. Solución: una API v2 versionada.
